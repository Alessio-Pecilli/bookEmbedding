# TVD-QAOA

A reproducible pipeline that solves **Triangle Vertex Deletion (TVD)** — both
the unweighted and weighted variants — with QAOA, and benchmarks it against
classical heuristic and exact solvers.

TVD: given a graph `G`, find a minimum-(cardinality|weight) vertex set `S`
such that `G - S` is triangle-free. Every triangle `{u, v, w}` imposes a
hitting-set constraint `x_u + x_v + x_w >= 1`; the objective is
`min sum_v w_v x_v` (unweighted = all `w_v = 1`).

## Qubit-minimization rationale (§2)

The hitting-set constraint is a 3-uniform hypergraph transversal, not an
edge constraint, so exactly penalizing its violation needs a **cubic**
penalty term `(1-x_u)(1-x_v)(1-x_w)`, which expands to the monomial
`x_u x_v x_w`.

- **Quantum annealers / QUBO** are restricted to quadratic (degree-2) terms,
  so a cubic term must be *quadratized*: introduce an ancilla `y_uv = x_u x_v`
  and substitute (`formulation.build_qubo`, Rosenberg-style, ancillas shared
  across triangles that reuse the same vertex pair). This costs one extra
  qubit per distinct pair-product — but it is **only built for the classical
  exact-QUBO cross-check**, never for QAOA.
- **QAOA's phase separator** only needs a Hamiltonian diagonal in the
  computational basis; it is not restricted to degree 2. A cubic
  `Z_u Z_v Z_w` term is implemented directly as a CNOT-ladder + `Rz` +
  CNOT-ladder multi-qubit phase gate (`qaoa.build_qaoa_circuit`), at the cost
  of extra two-qubit *gates*, not extra *qubits*. So the QAOA circuit uses
  **exactly one qubit per candidate vertex** — the standard PUBO-QAOA
  technique.
- **Second reduction**: a vertex in zero triangles is unconstrained and
  forced to 0 in every optimum, so it's dropped before any formulation is
  built (`formulation.prune_zero_triangle_vertices`). The instance generator
  already enforces "every vertex is in >= 1 triangle", so in practice this
  pass removes nothing — but it always runs, defensively, and logs a warning
  if it ever does remove something.
- The **ILP** formulation needs none of this: `x_u + x_v + x_w >= 1` is a
  native linear constraint (`formulation.build_ilp`).

`n_qubits_used` reported everywhere is the vertex count *after* pruning.

## Simulation backend (`qaoa.BackendConfig`)

QAOA circuit evaluation is pluggable, selected per-experiment via
`ExperimentConfig.qaoa_backend` / `qaoa_device` / `qaoa_mps_*`:

- **`aer_statevector`** (default) — exact statevector via pytket's
  `AerStateBackend`. Fine and preferred at small qubit counts, but full
  statevector memory is exponential (`2^n * 16 bytes`), so this is only
  viable up to roughly the low-to-mid 20s of qubits regardless of hardware.
- **`aer`** — shot-sampled `qiskit-aer` simulator (`simulation_method`
  `"automatic"`, i.e. statevector under the hood), `device="CPU"` or
  `"GPU"`. GPU requires a GPU-enabled `qiskit-aer` build (`qiskit-aer-gpu`)
  and CUDA on the host; it does not change the exponential memory scaling,
  just how fast each shot is generated.
- **`aer_mps`** — shot-sampled `matrix_product_state` (tensor-network)
  method, tunable via `qaoa_mps_max_bond_dimension` /
  `qaoa_mps_truncation_threshold`. This is what a server advertising
  "simulate up to 40 qubits via tensor networks" is running. **Caveat**:
  MPS truncates bond dimension between *adjacent* qubits in a 1D chain. This
  problem's `Z_uZvZw` phase terms are wired by triangle membership —
  arbitrary long-range 3-qubit gates, not nearest-neighbor — so MPS
  efficiency here depends on the actual entanglement generated by your
  graph's triangle structure and `p`, not just the qubit count. It is not
  guaranteed to be fast or accurate at 40 qubits just because the qubit
  count is nominally supported; benchmark it against `aer_statevector` on a
  small instance from the same generator before trusting results at scale.

  In this environment's `qiskit-aer` build, `AerSimulator(method=...).available_devices()`
  only reports `GPU` support at all when a GPU-enabled build + CUDA are
  present; check that on your target server rather than assuming `aer_mps`
  with `device="GPU"` works — MPS-GPU support varies by `qiskit-aer`
  version, and requesting an unsupported device raises at run time rather
  than silently falling back to CPU.

  See `configs/unweighted_large_mps.json` for an example large-`n`,
  MPS-backed config (`n_shots_optimization` there also caps shots used
  *during* angle optimization separately from the final reported evaluation,
  since every COBYLA iteration re-runs the circuit on a shot-sampled
  backend).

## QAOA layer-count (`p`) selection rule (§6)

For each instance: sweep `p = 1..p_max`. At each `p`, optimize `(beta, gamma)`
with a fixed number of random restarts (COBYLA), minimizing the *expected*
PUBO cost under the statevector distribution. Then sample `n_shots`
bitstrings from that distribution and take the minimum PUBO cost observed —
the **best-sampled objective**. Compute

```
approx_ratio = classical_optimal_objective / best_sampled_objective   (<= 1)
```

Select the **smallest `p`** whose ratio is `>= approx_ratio_threshold`
(default `0.99`). If no `p <= p_max` reaches it, the `p` with the best ratio
achieved is selected instead and the instance is flagged
`threshold_met = False`. The full per-`p` sweep (not just the winner) is
always saved.

## Package layout

```
tvd_qaoa/
  instances.py          # §3  reproducible instance generation + sweeps
  formulation.py         # §4  build_pubo / build_qubo / build_ilp, pruning
  classical_solvers.py   # §5  greedy heuristic, exact ILP, exact QUBO
  qaoa.py                 # §6  pytket PUBO-QAOA circuit + p-sweep
  experiment.py           # §7  orchestration, CLI, config-driven
  io_utils.py             # save/load instances & results
  analysis.py             # qubits-vs-size table + plot
tests/
  test_formulation_equivalence.py   # §4 cross-validation gate
configs/
  unweighted.json / weighted.json   # the two variants, same code path
```

## Running

```bash
pip install -r requirements.txt
pytest                                        # correctness gate (§4)
python -m tvd_qaoa.experiment --config configs/unweighted.json
python -m tvd_qaoa.experiment --config configs/weighted.json
python -m tvd_qaoa.analysis                   # qubits-vs-size table + plot
```

Results land in `data/results/results.csv` (one row per instance, schema in
`io_utils.RESULTS_COLUMNS`), per-instance angle/sweep artifacts in
`data/angles/{problem_type}/{instance_id}.json`, and the qubits-vs-size table
and plot in `data/results/analysis/`.

`gurobipy`/`docplex` are optional; `classical_solvers.solve_ilp` tries them
first and logs which backend actually ran (via `ilp_solver_backend` in the
results row), falling back to PuLP+CBC automatically if neither is
installed/licensed — the pipeline never hard-fails for lack of a commercial
license.

## Reproducing a single instance's result

Every instance is generated from a single integer seed via
`np.random.SeedSequence(seed).spawn(2)` (one sub-stream for graph topology,
one for weights) — no global RNG state. Given the same
`(n, seed, weighted, weight_low, weight_high)`, `instances.generate_instance`
reproduces a byte-identical graph and weight vector. The saved instance JSON
(`data/instances/{problem_type}/{instance_id}.json`) records `seed`,
`generation_params`, and `generator_version`, so any single result can be
regenerated exactly by calling `generate_instance` with those values and
re-running `experiment.run_instance` — the QAOA optimizer's random restarts
are themselves seeded from the instance's own seed.

`max_vertices` should be kept in a range simulable via statevector
simulation (`pytket-qiskit`'s `AerStateBackend`) — cost is exponential in
qubit count (i.e. in pruned graph size).
